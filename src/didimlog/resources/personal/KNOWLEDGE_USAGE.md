# Personal Knowledge 사용 방법

저장소 파일을 만들거나 고치기 전, 명령을 실행하기 전, 작업 절차를 답하기 전에 아래 조회를 먼저 한다. 작업이 짧거나 쉬워 보여도 건너뛰지 않는다. 이 조회를 생략한 채 작업을 시작하지 않는다. 한 작업에서 한 번 조회하고, 작업 주제나 지식 공간이 바뀌면 다시 조회한다.

1. 사용자 요청에 지식 공간 이름이 명시됐으면 그 이름을 `<scope>`로 선택한다. 명시하지 않았으면 현재 Git 최상위 디렉터리 이름을 `<scope>`로 선택한다.
2. `~/knowledge/index/<scope>.md`와 `~/knowledge/index/_global.md` 두 index를 각각 text search한다. 작업 관련 제목과 `찾을 때` 문구만 찾고, 두 파일을 처음부터 전부 읽지 않는다.
3. 명시한 `<scope>`의 index가 없어도 현재 Git 프로젝트로 바꾸지 않는다.
4. 일치한 항목은 index 제목만으로 적용하지 않는다. 관련도가 높은 순서로 최대 5건을 고르고, 반드시 `상세` 파일을 읽은 뒤 적용 여부를 판단한다.
5. 일치하는 항목이 없으면 추가 자료를 읽지 않고 작업을 계속한다.

저장소 파일과 무관한 순수 대화나 개념 설명만 요청받았을 때는 조회하지 않는다.

`lessons/`는 검증된 행동 규칙, `docs/`는 정확한 절차·계획, `book/`은 배경과 사례를 설명하는 해설이다.

자료를 저장할 때도 같은 `<scope>`를 사용한다. 명시한 `<scope>`를 현재 Git 프로젝트나 `_global`로 바꾸지 않는다.

적용 조건이 맞는 lesson은 지켜야 할 지침으로 사용한다. 검토 기한이 지났거나 반증·미검증된 내용은 확정 지침으로 사용하지 않는다.
